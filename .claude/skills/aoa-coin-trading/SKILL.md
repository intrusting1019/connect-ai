# 워뇨띠(aoa)식 코인 매매 스킬

방향을 맞히는 스킬이 아니다. 매 매매가 **"쏠린 자리의 반대편에서, 지정가로 나눠 받고, 버틸 수 있을 만큼만 싣는다"** 는 구조에 맞는지 점검한다. 규칙의 근거 수치는 [매매원칙.md](매매원칙.md), 매매 기술 분석은 [스킬분석.md](스킬분석.md).

## 절대 규칙 10 — 하나라도 어기면 매매하지 않는다
1. **자금** — 시드 3,000만 원까지는 현물 단타만. 선물엔 시드 일부만 격리로, 수익은 빼낸다.
2. **종목** — BTC 90% 이상. 알트 선물에서 역추세·물타기 금지.
3. **자리** — 7일 박스의 유리한 끝 0~25%에서만 (롱 하위 25%, 숏 상위 25%).
4. **방향** — 24시간 쏠림의 반대편. 큰 물량은 역추세와 박스 끝을 둘 다 충족할 때만.
5. **주문** — 시장가 금지. 진입·청산 모두 지정가로 나눠 미리 깐다.
6. **크기** — 분할 전부 체결 기준 실질 레버리지 3배 이하(평소 1~2배), 평단 -30%에도 청산 없음.
7. **이탈** — 롱은 7일 저점 이탈, 숏은 7일 고점 돌파 시 물타기 중단, 그날 안에 줄인다.
8. **변동성** — 7일/30일 변동성 1.5배 이상이면 방향 말고 과한 쏠림 되돌림만. 조용하면 쉰다.
9. **보유** — 방치 금지, 최대 14일. 쉴 거면 먼저 정리. 줄먹·히트앤런.
10. **도구** — 캔들·거래량·심리만. 보조지표·추세선 없음, 3분·30분·3시간·3일봉 제외.

## 판정 기준값

| 항목 | 계산 | 기준 |
|---|---|---|
| 박스 위치 | 롱 (현재가 − 7일 저가) ÷ (7일 고가 − 7일 저가), 숏 (7일 고가 − 현재가) ÷ 같은 폭 | 0~25% 자리 · 그 밖은 대기 (25~50%는 데이터상 유일한 손실 구간) · 0% 미만 = 박스 이탈 |
| 쏠림 | 현재가 vs 24시간 전 | 롱은 내리는 중, 숏은 오르는 중일 때 역추세 |
| 변동성 | 최근 7일 ÷ 30일 (1시간 수익률 표준편차) | 1.5배 이상 = 변동성 모드 |
| 크기 | 분할 전부 체결 명목가치 ÷ 증거금 | 3배 이하 (평소 1~2배), 청산까지 30% 이상 |
| 보유 | 진입 후 일수 | 14일 미만, 방치 0 |

7일 = 1시간봉 168개(진행 중인 봉 제외)의 최고·최저.

## 도구: `scripts/aoa_check.py`
공개 시세로 위 기준값을 계산하고 규칙대로 판정한 체크카드를 출력한다. API 키·주문 기능 없음, 파이썬 표준 라이브러리만 쓴다. 경로는 이 스킬 폴더 기준 (이 저장소에선 `.claude/skills/aoa-coin-trading/scripts/aoa_check.py`).

```bash
python3 scripts/aoa_check.py                                    # 바이낸스 BTCUSDT 롱·숏 판정
python3 scripts/aoa_check.py --exchange upbit --symbol KRW-BTC  # 업비트 원화 (bybit, binance-futures 도 가능)
python3 scripts/aoa_check.py --side long --equity 10000 --plan "67000:0.05,66600:0.05,66200:0.1"  # 분할 계획
python3 scripts/aoa_check.py --side long --equity 10000 --plan "66500:0.2" --held-days 5           # 보유 점검 (평단:수량)
python3 scripts/aoa_check.py --price 66800 --high7 72400 --low7 66100 --price24h 69000            # 직접 입력
```

- `시세 조회 실패`가 나오면 (네트워크 차단 등) 사용자에게 7일 고가·저가·현재가·24시간 전 가격을 받아 직접 입력으로 돌린다. 차트 캡처를 받았다면 1시간·4시간·일봉에서 읽는다.
- 원화 현물 계획은 `--spot`, 1시간봉 CSV는 `--csv`, 기계 처리는 `--json`.

## 작업 흐름

### A. "지금 들어가도 돼?" — 진입 점검
1. 스크립트로 체크카드를 뽑는다 (방향이 정해져 있으면 `--side`).
2. 스크립트가 못 보는 항목을 사용자에게 확인한다: 현물 단계·시드 구조(규칙 1), 끝까지 지켜볼 수 있는지(규칙 9), 지표·금지 봉으로 판단하고 있지 않은지(규칙 10).
3. ✅면 분할 지정가 계획을 제안한다.
   - 0~25% 구간 안에 지정가 3~4개. 7일 저점(롱)·고점(숏) 너머엔 깔지 않는다.
   - 총량은 증거금의 1~2배에서 시작해 `--plan`으로 3배 이하·30% 생존을 확인한다.
   - 익절 지정가(박스 중앙 부근 일부, 반대편 25% 구간 나머지)와 도망갈 기준을 같이 적는다.
4. ⏸·⚠️·⛔면 기다릴 가격(롱 자리 ≤ X, 숏 자리 ≥ Y)과 이유만 말하고 끝낸다. 규칙을 "이번만" 완화하지 않는다.

### B. 분할·레버리지 설계
`--plan` 결과에 ⛔가 있으면 손절 주문을 더하지 말고 첫 물량부터 줄여 다시 계산한다. 격리 모드라면 거래소 레버리지 설정값 자체를 3배 이하로 두라고 안내한다 (20배 격리 = 5% 역행에 청산).

### C. 보유 포지션 점검
방향·평단·수량·증거금(격리/교차)·보유 일수·앞으로 지켜볼 수 있는지를 받아 `--side … --plan "평단:수량" --equity … --held-days N`으로 돌린다. 결론은 하나만: ⛔ 정리 / ⚠️ 축소 / 💰 익절 / ✅ 유지(지킬 조건 명시). 곧 자리를 비울 예정이면 유지 판정이어도 정리를 권한다.

### D. 매매 복기
사용자가 준 체결 내역(거래소 CSV·캡처)을 포지션 0 → 0 단위 매매로 묶고, 매매마다 진입 박스 위치 · 24시간 역추세 여부 · 전부 체결 실질 레버리지 · 주문 방식 · 보유 시간 · 손익 · 어긴 규칙을 표로 만든다. 손익을 규칙 준수 매매와 위반 매매로 나눠 합계를 보여준다 — 워뇨띠도 원칙을 어긴 세 번에 크게 잃었으니, 위반 매매가 손실의 얼마를 차지하는지가 핵심이다.

## 출력 형식
스크립트 출력을 통째로 붙이지 말고 아래 형태로 압축한다.

```markdown
## 🧭 BTCUSDT 롱 점검 — ✅ 진입 구간
| 규칙 | 상태 | 값 |
|---|---|---|
| 2 종목 | ✅ | BTC |
| 3 박스 위치 | ✅ | 롱 18% (7일 66,100 ~ 72,400) |
| 4 쏠림 반대편 | ✅ | 24시간 -3.1% |
| 6 크기 | ✅ | 1.8배 · 청산 -55% |
| 8 변동성 | 평시 | 1.1배 |
| 1·9·10 | ❔ | 사용자 확인 필요 |

**계획** 지정가 67,000 / 66,500 / 66,200 · 익절 69,200(일부) / 70,900(나머지) · 도망갈 기준 66,100 이탈
> 판단 보조용 점검이며 투자 권유가 아닙니다.
```

## 하지 않는 것
- 가격 방향 예측·목표가 단정 ("오를 것 같다" 금지). 판정은 규칙 충족 여부로만 한다.
- 알트코인에 박스 끝 역추세·물타기 권유, 3배 초과 레버리지·시장가 진입 권유.
- 손실 중인 포지션의 규칙 밖 물타기를 정당화하기. 애매하면 대기가 답이다.
- 자동매매 봇으로 만들기. 워뇨띠도 서한에서 매매봇이 수익을 낼 것 같았다면 자료를 가진 자신이 먼저 돌렸을 것이라는 취지로 말했다. 이 스킬은 생각의 틀을 지키게 하는 점검 도구다.
